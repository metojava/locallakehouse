Open Lakehouse Workbench

Getting Started

A fully local lakehouse for SQL and PySpark over Delta Lake and Apache Iceberg. No cloud account, no external catalog, no cluster — just your machine.

Start in 5 minutes Full README Online book
New here? The backend is a FastAPI server that owns a single Spark session. The frontend is a React UI. You start both, open the browser, and use the SQL editor, PySpark editor, catalog, and storage views. Everything is stored under data_warehouse/ on your disk.

How it works

The backend runs one lazily-started local Spark session. All SQL and PySpark scripts share it, so temporary views and catalog state are visible everywhere. Two catalogs are registered:

CatalogEngineWarehouse on diskQuery form
spark_catalog (shown as delta) Delta Lake + Derby Hive metastore data_warehouse/delta db.table or spark_catalog.db.table
local_iceberg Iceberg Hadoop catalog data_warehouse/iceberg local_iceberg.db.table 
┌──────────────────────────────────────────────┐
│ React + TypeScript UI  (http://127.0.0.1:5173)│
│ SQL · PySpark · Databases · Schema · Storage  │
└───────────────────┬──────────────────────────┘
                    │ REST (FastAPI, 127.0.0.1:8000)
┌───────────────────▼──────────────────────────┐
│ FastAPI  /api/execute-sql  /api/execute-pyspark│
│          /api/tables  /api/import-file  ...    │
└───────────────────┬──────────────────────────┘
                    │
        Single local SparkSession (lazy)
        ├─ spark_catalog → Delta    ./data_warehouse/delta
        └─ local_iceberg → Iceberg  ./data_warehouse/iceberg

Prerequisites

  • Python 3.10 or newer (PySpark 4.1.4 runs on 3.10+).
  • Java 17 or newer — JAVA_HOME set and java -version works.
  • Node.js 20+ and npm (for the UI).
  • Internet on first launch to fetch the Delta/Iceberg connector jars from Maven Central.
  • Windows only: Hadoop winutils.exe and hadoop.dll. Set HADOOP_HOME to a folder whose bin\ contains them.
You do NOT need a global SPARK_HOME or a spark entry on PATH. The backend uses the Spark distribution bundled with the PySpark wheel in backend/.venv. Leaving an old Spark (for example 3.5.6) on PATH only causes confusion.

Quick start

From the repository root, open two terminals.

Terminal 1 — backend (FastAPI + Spark)

powershell -ExecutionPolicy Bypass -File .\scripts\start-backend.ps1

First run creates backend/.venv, installs dependencies, then starts Uvicorn on http://127.0.0.1:8000.

Terminal 2 — frontend (React UI)

powershell -ExecutionPolicy Bypass -File .\scripts\start-frontend.ps1

Installs npm packages on first run and starts Vite on http://127.0.0.1:5173.

Or start both at once

powershell -ExecutionPolicy Bypass -File .\scripts\start-all.ps1

Shortcuts on Windows (double-click / cmd)

scripts\start-backend.bat
scripts\start-frontend.bat
scripts\start-all.bat

Open the workbench

  • Workbench UI: http://127.0.0.1:5173
  • OpenAPI docs: http://127.0.0.1:8000/docs
  • Alternative UI copy: http://127.0.0.1:5174 (frontend-ts)
Manual launch (macOS / Linux or if scripts fail) 
# Backend
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload

# Frontend (new terminal)
cd frontend
npm install
npm run dev
On macOS/Linux you can also use ./scripts/start-backend.sh and ./scripts/start-frontend.sh.

First run & expect timing

  • The first SQL or PySpark request starts the Spark JVM and resolves connector jars. This can take 30–90 seconds.
  • After that the jars are cached in %USERPROFILE%\.ivy2* (Windows) or ~/.ivy2*, and subsequent sessions start in a few seconds.
  • The backend health indicator goes from Spark cold to Spark warm after the first request.
  • Check backend status any time: http://127.0.0.1:8000/api/health.
Fast path: if you only want to run PySpark locally, a warm session executes spark.range(100) in a few seconds. The long wait happens only on the very first start.

Spark settings (bundled vs local)

Open Spark Settings in the sidebar. By default the app uses the Spark bundled with PySpark 4.1.4 inside the virtual environment — nothing to install, no global SPARK_HOME needed. From this page you can:

  • Browse… to open a native folder picker on the backend machine, or type a path, then click Use this Spark.
  • Download & install a matching Spark release (about 570 MB) in the background, with progress.
  • Use bundled to revert.
Compatibility rule. A local Spark must be 4.1.x built for Scala 2.13. The Delta 4.3.1 and Iceberg 1.12 connectors are compiled for Spark 4.1 / Scala 2.13, and the PySpark client is 4.1.4. A spark-3.5.6-bin-hadoop3 install is Scala 2.12 and is rejected with an explanation.

A selected Spark home is saved to .runtime_settings.json (overrides LAKEHOUSE_SPARK_HOME) and the Spark session is restarted. Downloads extract to .spark_dist/.

Try it: SQL & PySpark

PySpark

from pyspark.sql import functions as F

df = spark.range(100).withColumn("value", F.rand())
df          # last expression → table preview

SQL

SELECT current_timestamp() AS first_query;
CREATE TABLE IF NOT EXISTS demo.orders (
  order_id BIGINT,
  customer_id BIGINT,
  total DOUBLE,
  ordered_at TIMESTAMP
) USING delta;

INSERT INTO demo.orders VALUES (1001, 1, 249.99, current_timestamp());
SELECT * FROM demo.orders;

Multi-statement scripts run in order; semicolons inside strings and comments are handled.

Seed demo data (optional)

Creates a Delta table demo.customers and an Iceberg table local_iceberg.demo.sales. 

cd backend
.\.venv\Scripts\Activate.ps1      # macOS/Linux: source .venv/bin/activate
python seed_demo.py
Stop the backend first. The embedded Derby metastore allows only one JVM at a time. Then run the seed script, then start the backend again. 
SELECT * FROM local_iceberg.demo.sales ORDER BY sold_at DESC LIMIT 100;

SELECT country, count(*) AS customers
FROM demo.customers
GROUP BY country
ORDER BY customers DESC;

Connect a database (optional)

Create databases.cfg in the repository root:

[postgresql.local_postgres]
name=Local PostgreSQL
host=localhost
port=5432
database=mydb
username=postgres
password=changeme

[mysql.local_mysql]
name=Local MySQL
host=localhost
port=3306
database=mydb
username=root
password=changeme

Then open Databases, list tables, and import them as Delta, Iceberg, or plain Spark tables. You can also manage connections from the Import → Database tab.

Configuration

Copy .env.example to .env in the repository root. Backend settings use the LAKEHOUSE_ prefix. Common ones:

VariableDefaultPurpose
LAKEHOUSE_WAREHOUSE_DIR<repo>/data_warehouseWhere tables live.
LAKEHOUSE_SPARK_METASTORE_DIR<repo>/.spark_metastoreEmbedded Derby metastore.
LAKEHOUSE_SPARK_MASTERlocal[*]Spark master URL.
LAKEHOUSE_SPARK_DRIVER_MEMORY2gDriver heap.
LAKEHOUSE_SPARK_HOMEunsetOptional external Spark 4.1.x (Scala 2.13).
LAKEHOUSE_SPARK_DIST_DIR<repo>/.spark_distWhere downloads extract.
LAKEHOUSE_QUERY_TIMEOUT_SECONDS300Per-statement timeout.
LAKEHOUSE_MAX_RESULT_ROWS1000Result row cap.

Restart the backend after changing Spark configuration — one session is created per process. Frontend API base URL: VITE_API_BASE_URL (default http://127.0.0.1:8000).

Troubleshooting

SymptomFix
UI shows “Backend offline”Start the backend and confirm /api/health. Check CORS/origin if the UI runs on another port.
First query hangs 30–90sNormal: Spark JVM startup + one-time jar resolution. Later runs are fast.
“Could not start Apache Spark”Verify Java 17+, JAVA_HOME, and internet/proxy access to Maven Central.
UnsatisfiedLinkError / winutils on WindowsSet HADOOP_HOME with winutils.exe + hadoop.dll in bin\, restart backend.
Local Spark rejected in Spark SettingsUse Spark 4.1.x built for Scala 2.13. 3.5.x / Scala 2.12 won’t load the connectors.
ClassNotFoundException for Delta/IcebergKeep Delta 4.3.x + Iceberg 4.1 runtime on Spark 4.1.x.
“Another instance of Derby may have already booted”Only one JVM may open the metastore. Stop the backend before running seed_demo.py or other Spark scripts.
Table exists on disk but TABLE_OR_VIEW_NOT_FOUNDIt was created by an older in-memory session. Recreate it or re-run seed_demo.py.
Port already in useChange the Uvicorn port and set VITE_API_BASE_URL; add the UI origin to LAKEHOUSE_CORS_ORIGINS.
Reset the lakehouseStop the backend, delete the contents of data_warehouse/ and .spark_metastore/ (keep the folders).
